## Phase Goal

Run one command and hear a generative loop in Sonic Pi — scale-locked, grid-aligned,
reproducible from its seed — reaching the speakers both by live OSC push and by an exported
`.rb` file.

> **Note on MVP user-story framing.** MVP mode is enabled for this phase, but the ROADMAP
> `**Goal:**` line above is not in `As a … / I want to … / so that …` form. The goal is quoted
> verbatim rather than reshaped, because inventing a user role and outcome the developer never
> stated would put words in their mouth. To get the canonical user story onto the ROADMAP goal
> line, run `/gsd mvp-phase 1` and re-plan; nothing else in this plan depends on it.

<objective>
Build the Walking Skeleton: the thinnest path that touches every layer this project will ever
have, wired end to end, in production quality. `bin/phonicpsy export --seed 42` goes
CLI -> Session -> Theory -> Arpeggiator -> IR -> Emitter -> Validator -> FileExporter -> a
`.rb` on disk that opens in the Sonic Pi editor and plays.

Purpose: prove the architecture before anything is layered on it. Every architectural decision
Phases 2-4 inherit — the structured IR (IR-01/IR-02/IR-03), the two-independent-RNG determinism
model (GEN-01/GEN-02/GEN-03), the generators-never-touch-Sonic-Pi-keywords rule, the shared
syntax gate (EMIT-03) — is exercised here on one path rather than asserted in a design document.
The offline transport comes first deliberately: it has zero external dependency risk, so a
failure here is a failure in this project's own Ruby, not in the Sonic Pi seam.

Output: a runnable Ruby project (`Gemfile`, `Rakefile`, `lib/phonicpsy/**`, `bin/phonicpsy`,
`test/**`) and an exported Sonic Pi program at `out/arpeggiator-42.rb`.

Locked decisions implemented here: D-01 (arpeggiator over a chord), D-02 (short progression, not
a held chord), D-03 (plain keyword args with defaults — no param DSL), D-04 (seeded randomness in
note order only; rhythm fixed), D-05 (`bin/phonicpsy` subcommands over a `Session`), D-06
(stdlib `optparse`), D-10 (A minor pentatonic default), D-12 (110 BPM, 16th grid), D-13 (the
Euclidean `spread` onsets ARE the density cap), D-14 (`:prophet`), D-18 (header carries generator,
seed and parameters only), D-19 (`out/<generator>-<seed>.rb`, gitignored).
</objective>

`lib/phonicpsy.rb` requires the theory, ir, generators, emit, and transport files explicitly —

`Phonicpsy::Theory::Scale` holds `NAMES` (a frozen `Set` of Sonic Pi scale names), `DEFAULT =
:minor_pentatonic` (D-10), `.valid?(name)` and `.validate!(name)`. For this task populate `NAMES`
with the full verbatim list of 157 names given in 01-RESEARCH.md "Pitfall A" — the planner's
decision is the complete list, not a curated subset, because a subset would make D-11's "any
scale name Sonic Pi itself knows" false. `.validate!` raises `ArgumentError` naming the offending
value. This module must know nothing about Sonic Pi's runtime, OSC, or the IR: it is a name
allowlist plus constants, usable in a bare `irb`.

`Phonicpsy::Theory::Chord` holds `DEFAULT_PROGRESSION = [:i, :iv, :ii, :v]` (D-02 — a short
progression, chosen over a held chord; degree symbols, not note names, so the progression is
scale-relative), `NOTES_PER_VOICING = 3`, and `.weight_profile(size)` returning descending powers
of two of that length (`[4, 2, 1]` for size 3) — the un-shuffled bias profile the generator
permutes. No interval arithmetic and no MIDI numbers appear in this file: Sonic Pi's
`chord_degree` does the pitch math at playback (GEN-04's "don't reimplement" rule).

`Phonicpsy::Theory::Rhythm` holds `MIN_SLEEP = 0.05`, `.euclid(onsets, steps)` and
`.step_sleep(grid)`. `.euclid` validates its arguments (see the acceptance criteria for the exact
boundary contract) and returns the onset count and step count as a validated pair for the Emitter
to render as Sonic Pi's own `spread` — do NOT reimplement Bjorklund in Ruby (01-RESEARCH.md
"Don't Hand-Roll"; `spread` is already the Toussaint algorithm). `.step_sleep(grid)` returns
`4.0 / grid` clamped up to `MIN_SLEEP`, always as a `Float` and always by float division — this is
the single choke point Pitfall 5 requires so no generator can ever emit a zero or negative sleep.

`Phonicpsy::IR` is the seam the whole design pivots on. `IR::Expr` is an abstract base with
`#to_sonic_pi`. `IR::Expr::Choice.new(options)` renders `options.map(&:inspect).join(", ")`
wrapped in brackets with `.choose` appended, except that a single-option Choice renders the bare
literal. `IR::Expr::Weighted.new(weights)` takes an insertion-ordered Hash of option =&gt; positive
Integer weight, exposes `#expanded` (each option repeated `weight` times, in insertion order, no
sorting), and renders the expanded array with `.choose` appended. Both raise `ArgumentError` on
empty input. `IR::Event` carries `voicing_index` (an `Expr`), `rotation` (an `Expr`), `gated`
(a Boolean — whether this grid slot is an onset) and `sleep_beats` (a Float literal).
`IR::Pattern` carries `loop_name`, `seed`, `bpm`, `synth`, `meta` (the keyword-argument values
the header prints) and `groups` — one group per progression degree, each holding the degree
symbol, the rotation `Expr`, the pitch `Expr`, the onset/step pair, and the per-step sleep.

The IR-03 property is structural and load-bearing: `Expr` nodes must reach the Emitter
**unresolved**. Nothing in `generators/`, `theory/` or `ir/` may call a random function; the
symbolic node is the value. This is what lets the same `IR::Pattern` later feed a Resolver for
streamed emission without rewriting the generator (ARCHITECTURE.md Anti-Pattern 2).

`Phonicpsy::Generators::Arpeggiator` (D-01) takes keyword arguments with defaults and nothing
else — no declaration DSL and no runtime introspection (D-03, so Phase 2's LOOP-02/03/04 stays
real work): `seed:`, `rng:`, `scale: Theory::Scale::DEFAULT`, `root: :a3` (D-10),
`progression: Theory::Chord::DEFAULT_PROGRESSION`, `bpm: 110`, `grid: 16` (D-12), `onsets: 7`,
`synth: :prophet` (D-14), `release: 0.18`, `amp: 0.7`. `.generator_name` returns `"arpeggiator"`.
`#pattern` returns an `IR::Pattern`.

Per D-04 the seeded Ruby `Random` decides note order only, never rhythm. Draw from `rng` in this
exact fixed order, once per progression degree (a fixed draw order is what Pitfall 7 requires):
first `Theory::Chord.weight_profile(NOTES_PER_VOICING).shuffle(random: rng)` to get that degree's
weight permutation, then `(0...NOTES_PER_VOICING).to_a.sample(2, random: rng).sort` to get that
degree's two rotation options. Build `IR::Expr::Weighted` from the voicing indices zipped with
the shuffled weights, and `IR::Expr::Choice` from the sorted rotation options. Because the profile
is a permutation of distinct values it is never uniform, so GEN-08's "weighted rather than
uniform" holds for every seed. Onsets stay at a fixed `spread onsets, grid` for every degree —
rhythm does not vary with the seed (D-04), and the empty slots in that spread ARE the rests and
ARE the density cap (D-13): there is no separate rest probability and no notes-per-bar filter.

`Phonicpsy::Emit::SonicPiEmitter` is the ONLY place in the project allowed to build a Sonic Pi
source string, and it makes no musical decisions (ARCHITECTURE.md's load-bearing rule).
`LOOP_PREFIX = "phonicpsy_"`, `STOP_FLAG = :phonicpsy_stop`. `.render(pattern)` produces, in this
order: a header comment block carrying generator name, seed, and each keyword-argument value from
`pattern.meta`, one per line, and nothing else — no timestamp, no absolute path, no hostname,
nothing that varies between runs (D-18, and Success Criterion 3 is defined by the byte-identical
diff); a blank line; then `live_loop :phonicpsy_arpeggiator do`. The first statement inside the
loop body is `use_random_seed &lt;seed&gt;` (GEN-03 — verified against Sonic Pi's own A.09 tutorial
idiom), then `use_bpm` and `use_synth`. Put `use_bpm` and `use_synth` INSIDE the loop body, never
at top level: Sonic Pi's `use_*` settings are thread-local and top-level code does not re-apply on
a live_loop redefinition (Pitfall 4), so a re-push would silently keep the old tempo.

The loop body iterates the progression degrees. For each group emit a `chord_degree` call
parameterised by the degree symbol, the root, the scale name and `NOTES_PER_VOICING`; assign the
rotation from the `Choice` node's rendered form; then iterate `(spread onsets, grid).each` with a
block parameter for the onset boolean. Inside the step, emit a `play` call indexing the voicing
ring at rotation plus the `Weighted` node's rendered form, carrying `release:` and `amp:`,
suffixed with a trailing `if` on the onset boolean so rests are genuinely silent; then the
`sleep` line with the Float literal from `Theory::Rhythm.step_sleep`. Sonic Pi's ring indexing
wraps modulo size (verified at `core.rb:896`, `RingVector#map_index`), so rotation plus index can
exceed the voicing size safely. The `sleep` is unconditional — it is outside the `if` — which is
what keeps every onset on the declared 16th grid (GEN-07) and guarantees the loop always sleeps
(Pitfall 5).

`Phonicpsy::Transport::Validator` knows nothing about the IR or generators — it receives a
finished `String` (ARCHITECTURE.md internal boundary). `MAX_PAYLOAD_BYTES = 8192` (D-20).
`.syntax!(code)` raises `Validator::SyntaxError` carrying the first 200 characters of the offending
source when `Ripper.sexp(code)` returns nil (EMIT-03 — fail loudly, never silently).
`.size!(code)` raises `Validator::PayloadTooLargeError` naming the actual bytesize and the cap when
`code.bytesize` exceeds `MAX_PAYLOAD_BYTES`. Define both here; only `.syntax!` is called on the
export path (plan 01-03 calls `.size!` on the push path, where the datagram ceiling applies).

`Phonicpsy::Transport::FileExporter` has `DEFAULT_DIR = "out"`,
`.default_path(generator_name, seed)` returning `out/&lt;generator&gt;-&lt;seed&gt;.rb` (D-19), and
`.write(code, path)`. `.write` expands the path, creates the parent directory, writes to a
temporary file **in that same directory**, then `File.rename`s it into place — the rename is
atomic within a filesystem, so no reader ever sees a half-written program. Return the expanded
path.

`Phonicpsy::Session` is the top of the stack and the only object allowed to know about all the
others (D-05 — the CLI is a thin wrapper over it, so Phase 2's hot-reload loop reuses this object
rather than reimplementing it). `.new(seed:, **params)` stores the master seed, builds exactly one
`Random.new(seed)` and exposes it as `#rng`, and instantiates the Arpeggiator with it. `#emit`
calls `generator.pattern`, renders it through `SonicPiEmitter`, passes the result through
`Validator.syntax!`, and returns the string. `#export(path: nil)` calls `#emit` and hands the
string to `FileExporter.write`, defaulting the path from the generator name and seed.

`Phonicpsy::CLI.run(argv)` uses stdlib `optparse` only (D-06 — no CLI gem, so the core dependency
list stays at `osc-ruby` alone and startup stays fast). It dispatches on `argv.shift` and supports
`export` with `--seed SEED` (coerced with `Integer()`) and `--help` in this task. On success it
prints the seed and the written path to stdout and returns 0. On an `ArgumentError`,
`Validator::SyntaxError` or `Validator::PayloadTooLargeError` it prints the message to stderr and
returns a non-zero status — never a stack trace and never a silent success.

## Planner decisions not covered by CONTEXT.md "Claude's Discretion"

- **Scale-name list size (RESEARCH Assumption A3).** CONTEXT.md D-11 assumed ~40 names; the
  installed Sonic Pi defines 157. This plan embeds the **full verified 157-name list**, because a
  curated subset would make D-11's "any scale name Sonic Pi itself knows" false and would reject
  valid input at the wrong layer.
- **Ruby-side RNG consumers.** D-04 locks seeded randomness to note order, and the pitch/rotation
  picks are symbolic, so without a deliberate choice the Ruby `Random` would have no consumer at
  all and GEN-02 would be vacuous. This plan gives it two: the per-degree weight permutation and
  the per-degree rotation options. Both are note order, neither is rhythm, and both change the
  emitted bytes per seed — which is what makes GEN-01's byte-identity test meaningful.
